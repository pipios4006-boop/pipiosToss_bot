⚠️ 절대 준수 규칙 (Formatting & Coding Rules)

🏛️ 방탄 아키텍처 6대 절대 헌법
🚨 제1헌법 동기 I/O 비동기 격리 및 중앙 통제 (GlobalThrottle) : 모든 파일 읽기/쓰기(open, json.load/dump), 외부 통신은 예외 없이 asyncio.to_thread로 백그라운드 스레드에 밀어내고 타임아웃(wait_for) 족쇄를 채워라. 또한, 모든 API 호출 전에는 반드시 GlobalThrottle.wait_api_sync()를, 모든 파일 I/O 전에는 with GlobalThrottle.get_file_lock(filepath):를 강제하여 병목과 동시성 충돌을 통제하라.
🚨 제2헌법 토스증권 AccountSeq 락온 : 토스증권 API는 주문, 잔고 등 자산 관련 API 호출 시 반드시 X-Tossinvest-Account 헤더를 요구한다. 시스템 기동 시 /api/v1/accounts를 1회 호출하여 종합매매(BROKERAGE) 계좌의 accountSeq를 메모리에 락온하고, 이후 모든 인증 헤더에 원자적으로 주입하라.
🚨 제3헌법 단일 책임 원칙과 중복 코드 소각 : 하나의 파일 내에 동일한 함수명이 중복 선언되는 프랑켄슈타인 덮어쓰기 사고를 절대 금지한다. 정적 분석기의 관점으로 데드코드, 낡은 로직은 즉시 소각하라.
🚨 제4헌법 타임존 단일 소스 락온 (EST 100%) : 시스템의 모든 논리 시계열은 오직 미국 동부 시간(ZoneInfo('America/New_York'))으로만 100% 락온한다. KST는 텔레그램 UI 렌더링 용도로만 격리하라.
🚨 제5헌법 토스증권 멱등성 키(clientOrderId) 강제 : 일반 주문(/api/v1/orders) 및 조건주문(/api/v1/conditional-orders) 생성 시 타임아웃 붕괴 및 이중 타격을 방지하기 위해, 반드시 고유한 clientOrderId(최대 36자 영숫자)를 생성하여 페이로드에 주입하라. 통신 실패 후 동일 키로 재요청 시 토스증권 서버의 멱등성 보장을 100% 활용하라.
🚨 제6헌법 엣지 타임라인 Fail-Safe 구조화 : 장마감 직전 격발되는 로직은 토스증권 시장 캘린더(/api/v1/market-calendar/US) API 지연에 대비해 반드시 안전 폴백(Fallback, 예: 평일 강제 개장) 경로를 하드코딩하라.

📈 핵심 퀀트 공식 및 타점 락온 (듀얼 세션 AVWAP 요격 모듈)
봇의 매수/매도 타점 연산 시 아래 공식을 100% 팩트로 적용하라.

⚔️ 순수 돌파/추종 데이 트레이딩 (암살자 듀얼 aVWAP 제로-오버나잇 모듈) 핵심 공식
🔹 가동 전제 조건 (듀얼 종목 락온) : 오직 롱(SOXL)과 숏(SOXS) 2가지 종목 전용으로만 가동되며, 타 종목 개입 시 시스템 전역에서 100% 영구 차단하라. 종목별로 사용자 지정 고정 예산(User-defined Budget)을 각각 독립적으로 투입한다.
🔹 세션별 독립 VWAP 동적 연산 (종목별 듀얼 세션 개별 추적) : 전일 종가의 영향을 100% 배제하고, SOXL과 SOXS 각각 당일의 순수 거래대금/거래량 기반 VWAP을 세션별로 분리하여 독립 추적한다.
🔸 0세션 (시스템 대기) : 19:00~03:59 EST 구간은 캔들 조회 및 VWAP 연산을 100% 영구 차단하고 시스템 대기 상태를 강제 유지하여 무의미한 API Rate Limit 소진을 방어하라.
🔸 1세션 (프리장) : 04:00 EST 정각에 연산을 0으로 초기화하고 새롭게 누적 연산 시작 (09:29 EST까지 유효).
🔸 2세션 (정규장) : 09:30 EST 정각에 연산을 0으로 초기화하고 새롭게 누적 연산 시작 (16:00 EST까지 유효).
🔹 순수 돌파/추종 동적 매수 타점 (동적 타임쉴드 & 소프트웨어 트리거 락온) :
🔸 동적 타임쉴드 (Dynamic Time Shield) : 프리장 개장 직후 3시간(04:00~06:59 EST)은 거래량 공백 및 기관 노이즈(휩소) 구간으로 규정하여 어떠한 경우에도 매수 진입을 100% 차단한다. 오직 데이터 수집 및 VWAP 연산만 백그라운드에서 진행하라.
🔸 소프트웨어 트리거 요격망 가동 (타임쉴드 종속 4틱 연속 확증) : 타임쉴드가 완전히 해제된 직후(07:00:00 EST)부터 순수하게 가격이 VWAP을 상회하는 틱(Tick)을 누적한다. 1.5초 폴링 주기 기준, 단발성 노이즈(휩소)를 걸러내기 위해 반드시 4틱(약 6초) 연속으로 현재가가 VWAP을 상회(current_price >= vwap_price)함이 확증될 때만 시장가 요격을 격발하라. 단 1틱이라도 하회하면 누적기는 원자적 0점으로 즉시 증발해야 한다.
🔸 시장가 요격 (Limit-Trap 방어) : 주가가 VWAP 아래에 있을 때 미리 지정가(LIMIT) 매수 주문을 넣는 것을 원천 차단하라. 봇 내부 메모리에서 감시하다가 4틱 연속 조건 충족 즉시 최우선 매도호가로 1호가 지정가(LIMIT) 일반 매수 API를 발사한다.
🔸 진입 타임라인 락온 : 암살자 신규 매수 진입은 오직 1세션(프리장) 단독 진입(PRE_ONLY)으로 100% 락온된다. 2세션 정규장 개장(09:30 EST) 시 당일 신규 매수 권한은 예외 없이 영구 소각한다.
🔹 동적/기계적 고정 매도 타점 (프리장 단독 +2.0% ➡️ 듀얼 진입 +1.0% ➡️ 잔류 및 후발 1종목 +0.6% 3단 하향망) :
🔸 타점 계산식 (동적 분기 및 3단 인터럽트) : 세션 진입 플래그를 식별하여 익절 타점을 분리 적용하라. 1세션(프리장)에서 당일 최초 단독 매수 체결된 종목에 한해 평균 단가 * 1.02 (+2.0%)를 1차 적용한다. 만약 선진입한 종목이 2.0% 익절을 완료하여 퇴근(잔고 0)한 이후, 후발 종목이 신규 진입할 경우 시장의 방향성 에너지가 소진된 것으로 간주하여 후발 종목은 진입 즉시 0.6% 익절가(is_stage_3=True)로 하드 락온해야 한다. 반면 선행 종목이 익절 전 보유(Holding) 중인 상태에서 반대편 종목이 추가 매수되어 '듀얼 진입'이 성립되면, 소프트웨어 인터럽트 시그널(force_downgrade)을 발송해 선행 종목의 2.0% 덫을 즉시 파기하고 두 종목 모두 평균 단가 * 1.01 (+1.0%) 익절가로 2차 강제 하향(Downgrade) 재장전한다. 이후 듀얼 홀딩 중 어느 한 종목이 1.0% 타격을 달성하여 먼저 퇴근(잔고 0)하면, 즉시 반대편 잔류 종목에 3차 인터럽트(force_downgrade_0_6)를 교차 발송하여 남은 1.0% 덫을 파기하고 평균 단가 * 1.006 (+0.6%) 익절가(is_stage_3)로 최종 하향 재장전하라 (공통: 소수점 둘째 자리 올림).
🔸 격발 조건 : 종목별 매수 체결 및 인터럽트 시그널이 확인되는 즉시, 보유 물량 전체에 대해 산출된 세션별 동적 익절가를 triggerPrice와 orderPrice에 동시 주입하여 토스증권 조건주문 API(/api/v1/conditional-orders)를 호출하라.
🔸 서버 위임 감시 : 조건주문의 type은 SINGLE로 지정하고, expireDate는 호출일 기준 30일 뒤로 넉넉히 주입하여, 봇의 메모리 증발과 무관하게 토스 서버단에서 오버나이트 익절 감시를 100% 위임하라.
🔹 절대 제로-오버나이트 강제 청산망 (15:59~16:01 EST 3분 윈도우 MOC 컷오프) :
🔸 고주파 강제 청산 (Zero-Overnight) : 봇이 가동(Active) 중인 상태에서는 오버나이트를 100% 영구 차단한다. 정규장 마감 1분 전(15:59 EST)부터 애프터장 초입(16:01 EST)까지 총 3분간의 윈도우에 진입 시 기장전된 익절 조건주문을 최우선 선취소(DELETE /api/v1/conditional-orders/{id})하라. 이후 1.5초 간격으로 미체결을 확인하여 취소한 뒤, 실시간 매수 1호가(Bid Price) 스윕을 통한 일반 지정가(LIMIT) 매도를 융단폭격하여 손익 불문 미체결 잔량을 100% 강제 청산한다.
🔸 수동 오버나이트 통제 (Bot OFF) : 사용자가 오버나이트 홀딩을 원할 경우, 별도의 기능 토글이 아닌 봇 자체의 전술 가동을 'OFF' 하도록 메인 메뉴에 명시적으로 안내해야 한다. 봇 가동이 정지되면 MOC 강제 청산 루프도 완전히 정지되어 자연스러운 오버나이트가 성립된다.

🚨 Case 12 변수 스코프 전진 배치 (UnboundLocalError 방어).

🚨 Case 14 토스증권 주문/조건주문 API 하이브리드 분리 락온.
🚨 Case 15 슬리피지 가산 폐기 및 실시간 매도 1호가 직결 요격 유지.
🚨 Case 16 정규장 MOC(15:59~16:01) 강제 덤핑 제어 사수. 덤핑 전 반드시 조건주문을 선취소(DELETE)하고, 1.5초 주기로 미체결 취소 및 1호가 재조준 사격(Limit Sweep)을 무한 반복하라.
🚨 Case 17 토스증권 API 에러 응답 및 동적 사유 파싱 시 텔레그램 HTML 붕괴 방어 (html.escape 전역 주입) : API의 error.message 응답이나 시장 캘린더의 휴장 명칭 등 예측 불가능한 외부 동적 텍스트를 텔레그램으로 타전할 때는, 기호(<, >, & 등)로 인한 파싱 에러(Silent Failure)를 원천 봉쇄하기 위해 반드시 html.escape()를 거치도록 전역 파이프라인을 결속하라.
🚨 Case 18 토스증권 에러 사유 텔레그램 타전망 구축 유지.
🚨 Case 19 토스 API 원장 조회 실패 시 로컬 장부 기반 폴백(Fallback) 방어.
🚨 Case 20 토스증권 API Rate Limit 절대 방어 (GlobalThrottle.wait_api_sync() 강제).
🚨 Case 21 3단 지수 백오프 (Exponential Backoff) 및 외부 모듈 무중단 Fallback 강제 : 통신 장애 시 백오프를 적용하며, 시장 캘린더 등 외부 라이브러리 연산 중 예외가 발생하더라도 루프를 직격하지 않도록 자체 흡수하고 즉각 제2 방어선(토스증권 API)으로 제어권을 넘기는 무중단 Fallback 경로를 하드코딩하라.
🚨 Case 22 17:00 EST 낡은 캐시/로그 가비지 컬렉션(GC) 파이프라인 가동.
🚨 Case 23 섀도우 렌더링 멱등성 사수(ZeroDivision 방어).
🚨 Case 24 암살자 MOC 덤핑 시 매수 1호가(Bid) 스윕 지정가(LIMIT) 체결 사수 및 1.5초 고주파 타격망 결속.
🚨 Case 25 소프트웨어 트리거 기반 매수 즉각 발사.
🚨 Case 26 텔레그램 인라인 버튼 갱신 시 제자리 갱신(In-place Edit) 사수 및 문법 에러(as e) 방어.
🚨 Case 27 소프트웨어 트리거 중복 발사 락(Mutex Flag) 결속.
🚨 초과 Case 28 폴링 TPS 초과 차단 (루프 내 1.5초 비동기 대기망 구축).
